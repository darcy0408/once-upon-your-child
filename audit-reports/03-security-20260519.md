## Executive summary

Story Weaver has had two substantial security remediation batches land since
the prior audit (2026-05-16/17). This audit verified that work against current
source: of 21 prior findings spot-checked, 20 are confirmed fixed — token
revocation, short-lived JWTs, secure mobile storage, webhook tier-from-price
resolution, webhook idempotency, non-root containers, multi-stage Docker
builds, recursive input sanitization, hero-name pseudonymization, the
production guard on the test-account endpoint, and more. The payment layer in
particular is above industry baseline: Stripe webhook tier resolution reads the
actual charged price ID and fails closed to the free tier on an unknown price,
event replay is deduped by a unique-constrained table, and out-of-order events
are dropped by a per-user high-water-mark cursor. IAP receipt verification
fails closed while store credentials are unprovisioned.

As a result this audit found NO new Critical finding and only ONE new High.

The single High (S-01) is that the application-wide rate-limit key function
trusts a client-supplied `X-User-ID` request header when no authenticated user
is attached. An attacker brute-forcing `/auth/login` can send a fresh random
`X-User-ID` per request, landing every attempt in a new limiter bucket and
fully bypassing the `10 per minute` login limit and the global daily/hourly
defaults. The same header can be set to a victim's id to exhaust their bucket
and lock them out. It is a small, pure code fix.

Five Medium findings cluster in the seams the prior remediation work packages
did not own: a 1,700-line `security/` directory that no shipping code imports
(dead controls that read as live — a governance risk); BYOK API keys encrypted
with unauthenticated AES-256-CBC rather than an authenticated mode; three
`/usage/*` admin endpoints that still echo raw exception strings (a partial
regression of the prior L-7 fix); an avatar rate-limiter held in a per-process
dict that under-counts by the worker count and leaks memory; and IAP
server-to-server notification endpoints that are unauthenticated stubs today
and must gain signature verification before their phase-2 entitlement logic
lands.

One prior finding, H-8 (verifiable parental consent), is code-complete but
gated OFF by the `COPPA_REQUIRE_VERIFIED_CONSENT` flag for the tester phase.
That flag must be set true before public launch — a launch-gate decision, not
a defect.

No CSAM-adjacent, grooming, or minor-manipulation vector was found in the
security surfaces audited here. PCI SAQ-A scope is preserved. The recommended
sequence ships S-01, S-02 and S-04 (all small, pure code changes) before
launch, with the three remaining Medium items in the next engineering cycle.

### Critical and High — proof-of-exploit

**No new Critical.** All prior Criticals (C-1, C-2, C-3) resolved or
accepted-by-disclosure.

**S-01 (High)** — `get_user_identifier` is the flask-limiter `key_func`
(`app.py:304`). With no authenticated user it returns `user:{X-User-ID header}`
(`app_helpers.py:51-61`), a value the caller fully controls, consulted before
the IP fallback. An attacker brute-forcing `/auth/login` (rate-limited
`10 per minute`) sends a unique random `X-User-ID` per request; every attempt
lands in a new bucket and neither the route limit nor the global
`200/day · 50/hour` default is ever reached — the brute-force limit is fully
bypassed. Conversely, sending 50 requests with `X-User-ID: <victim_id>`
exhausts the victim's bucket (limit-exhaustion DoS). Fix: key unauthenticated
requests strictly on `get_remote_address()`; remove the `X-User-ID` identity
fallback (the Flutter client uses `Authorization: Bearer`, not this header).
Pure code fix.

### Compliance

- COPPA §312 — verifiable-consent infrastructure present but flag-gated OFF

  obligations are met in current source.
- PCI DSS SAQ-A — eligibility preserved; all card handling is hosted-redirect;

- OWASP LLM Top 10 — injection (LLM01), sensitive-info disclosure (LLM02),

### Remediation status (2026-05-19, post-audit)

- **S-01 — FIXED.** `get_user_identifier()` and `get_user_tier()`
  (`backend/utils/app_helpers.py`) no longer consult the client-supplied
  `X-User-ID` header; rate-limit identity now comes only from auth-middleware
  context or a verified JWT, falling back to remote IP. The matching
  `X-User-ID` fallback in `get_current_user_id()` (`backend/middleware/auth.py`)
  was also removed. Full backend suite green (905 passed).
- **S-04 — FIXED.** `/usage/summary`, `/usage/daily`, and `/usage/mock-mode`
  (`backend/routes/utility_routes.py`) no longer return `str(e)` in the
  response body; the exception is still logged via `logger.exception`.
- **S-02 — FIXED.** The dead `security/` directory (1,746 LOC) and its only
  consumer (the orphan `test_iam_manager_isolation` test) were deleted. Git
  history preserves the code.
- **S-03 — FIXED.** BYOK keys now use AES-256-GCM (authenticated encryption).
  `encrypt_api_key` emits a versioned `gcm:`-prefixed blob; `decrypt_api_key`
  stays backward-compatible with legacy AES-256-CBC blobs and a GCM auth-tag
  failure raises (tamper detection). `decrypt_user_api_key()` lazily re-wraps
  legacy keys to GCM on access — no migration downtime.
- **S-05 — FIXED.** The avatar rate limiter moved from a per-process dict to
  Redis (`INCR`+`EXPIRE`), accurate across gunicorn workers and self-evicting.
  The in-process fallback now prunes stale hour-buckets (memory-leak fix).
- **S-06 — FIXED.** New `iap_notification_verify.py` adds Apple JWS x5c-chain
  verification and Google Pub/Sub OIDC verification, wired as a hard gate on
  the Apple/Google S2S notification endpoints: unverified → 403, missing
  config → 503 (fail closed). Endpoints still do not mutate entitlement.
- **S-07 — FIXED.** JWT TTLs moved to the `Config` class (applied before
  `JWTManager()` is constructed) instead of a post-init `setdefault`.
- **S-09 — FIXED.** `/debug-gemini` and `/debug-openrouter` now return 403
  when `is_production()` — no live metered AI calls in production.
- **S-11 — FIXED.** `/auth/login` gained a Redis-backed per-account
  failed-login counter; attempts past the threshold return 429. The password
  is checked first, so a correct password is never locked out.
- **S-08 — FIXED.** The nginx CSP `connect-src` was tightened from a
  `https: wss:` wildcard to the two concrete origins the production app
  calls — the Railway backend API and the Sentry ingest host. Confirmed via
  the Railway API that the production frontend (grand-light) sets no backend-
  URL override, so it uses the hardcoded default backend.
- **S-10, S-12, S-13 — open** (Informational); no action this cycle.

Backend test suite: 943 passed after all remediations.
