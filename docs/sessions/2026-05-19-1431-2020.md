# SESSION CLOSE — 2026-05-19 14:31 [2020] — Branch: main — MT-129 text-fidelity fix: story illustrations now match the created avatar

## Accomplished
- **MT-129 — text-fidelity fix shipped** (commit `68df77de`). Story illustrations
  were rendering a generic child instead of the created character. Traced it to
  the avatar's real appearance being dropped at three handoffs and then
  *replaced* with a confident fabricated description:
  1. `backend/services/avatar_generation_service.py` — `generate_custom_avatar`
     ran a photo-feature vision call (`hair_style`/`skin_tone`/`distinguishing`)
     but discarded the result after prompt assembly. Now merged into the
     returned `attributes` (all 3 return paths, via a shared `avatar_attributes`).
  2. `lib/screens/wizard_steps/hero_creator_step.dart` — saved `GeneratedAvatar`
     with a hardcoded `attributes: {'source':'custom_photo'}`, dropping even the
     features the backend did return. Now spreads the real attributes in.
  3. `lib/story_result_screen.dart` — `_characterAppearanceForBackend` ran every
     field through mappers (`_mapHairColor` etc.) that return a **non-null
     default** (`brown` hair / `light` skin) when the source is empty, so the
     backend was always handed a confident, wrong description. Rewritten to emit
     only fields backed by real data (omit unknowns), and to fall back to live
     `wizardData.generatedAvatar` for unsaved/anonymous characters.
- New plumbing: `CharacterAvatar.generationAttributes` (`lib/avatar_models.dart`)
  carries the backend features from `CustomAvatarScreen` to the saved avatar.
- `backend/gemini_image_generator.py` — `build_appearance_details` now also
  emits the `distinguishing` cue (glasses/freckles).
- Added `TestBuildAppearanceDetails` (5 tests) to
  `backend/tests/unit/test_image_routing.py` locking in the no-fabrication
  contract. `flutter analyze` clean on 4 files; 40 backend tests pass.
- Confirmed (no change needed): BYOK users (own Gemini key) already get
  illustrations grounded on the avatar image — the per-page prefetcher sends
  `user_api_key` + `custom_avatar_base64`, and `gemini_image_generator`
  decodes it as a reference Part (data-URI prefix stripped correctly).
