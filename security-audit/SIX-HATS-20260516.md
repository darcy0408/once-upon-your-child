# Six Hats Security Audit — Story Weaver

Date: 2026-05-16
Repository: `C:\dev\story-weaver-app` (commit `0de9f590`, branch `main`)
Method: Edward de Bono's Six Thinking Hats, applied read-only across mobile, API, infrastructure, payments, AI-injection, and child-safety surfaces.
Frameworks: OWASP Top 10 (2021), OWASP API Top 10 (2023), OWASP Mobile Top 10, OWASP LLM Top 10, COPPA §312, GDPR-K, PCI DSS SAQ-A.
Audience of the application: children ages 3–17.

This is the primary report. Per-hat sub-files are in the same directory (`WHITE-HAT.md` … `BLUE-HAT.md`).

---

## Executive Summary

Story Weaver is, on balance, a security-conscious codebase: it has fail-fast JWT-secret assertions, a hash-pinned dependency lockfile, a 14-pattern prompt-injection filter, an explicit CORS allowlist, age-band-aware LLM safety settings, and a correctly signature-verified Stripe webhook. These are not table stakes for a solo-built app, and they materially reduce the attack surface. The audit nonetheless found 3 Critical (one — C-2 — confirmed resolved during the audit), 8 High, and roughly 17 Medium issues, concentrated in two themes.

The first theme is a gap between what the app promises and what the code does. The privacy policy and the parental-consent screen both state, emphatically, that avatar photos "never leave this phone." The code uploads a child's selfie to the backend (`custom_avatar_screen.dart:435`). The BYOK wizard states the user's Gemini key "stays on your device — we never see it"; the code sends that key to the backend on every story request. Because COPPA and GDPR require consent to rest on accurate notice, these misstatements do not just risk a trust problem — they arguably void the consent the app collects. This is the single most important finding class.

The second theme is child-safety surfaces that lack defense-in-depth. Free-text fields a child (or a tampered client) controls — interactive-story custom choices, "world bible" text, and avatar/pet refinement notes — reach the LLM and image models without the sanitization applied to the main story path. Combined with a custom-avatar flow that pairs a real minor's uploaded photo with unvalidated free text, this creates a CSAM-adjacent risk that the audit rates Critical regardless of CVSS. Content moderation across the codebase consistently "fails open": a provider outage silently disables filtering while stories still ship to a four-year-old.

A Gemini API key was committed to git history. During this audit it was tested against Google's API and found already expired (`API_KEY_INVALID`), so the exposure is closed — the dead key string remains in history but has no value. C-2 is retained below for the record, marked RESOLVED.

None of this requires a rewrite. The Critical and High items are a focused two-to-three-day remediation: rotate the key, correct the privacy claims (or make them true), sanitize the bypassed prompt fields, move tokens to secure storage, and implement a real verifiable-consent method. The Blue Hat section sequences this work. PCI scope is correctly minimal (SAQ-A — no card data touches the server).

- JWT, `HS256`, pinned algorithm. Access token TTL 24h, refresh 30 days. Two parallel auth stacks coexist — raw `PyJWT` in `backend/middleware/auth.py` and `flask_jwt_extended` in `utility_routes.py`/`achievement_routes.py`.

- Anonymous-user bootstrap; refresh-token rotation with Redis JTI blocklist.
- COPPA gate `require_parental_consent` and server-side `g.minor_age_cap` for declared under-13 accounts.

### Endpoints / blueprints
17 route blueprints: `user`, `admin`, `api_key`, `story`, `avatar`, `avatar_gallery`, `character`, `chronicle`, `progression` (unregistered), `achievement`, `stripe`, `subscription`, `tts`, `health`, `utility`, `webhook_handler`, `analytics`.

- Required secrets (`JWT_SECRET_KEY`, `GEMINI_API_KEY`, `DATABASE_URL`) loaded from env; `_get_required_secret` raises in production if absent. No hardcoded production fallbacks.
- BYOK Gemini keys encrypted at rest, AES-256-CBC + random IV (`backend/encryption_utils.py`); never serialized in `to_dict()`.
- `backend/.env` is no longer tracked but was committed historically (see C-2).

### Data flows / third parties
- LLM story generation: Google Gemini (primary), OpenRouter (fallback).
- Image generation: Gemini, OpenRouter, Cloudflare Workers AI (Flux), Replicate (Flux Schnell).
- TTS: ElevenLabs. Payments: Stripe (hosted checkout + portal). Analytics/crash: Firebase Analytics, Sentry.
- Child PII (first name, age, feelings text, uploaded photo) reaches the backend and onward to LLM/image providers.

### COPPA data touchpoints
Child first name, declared age, selfie/photo, emotional-state ("big feelings") text, caregiver names, and a persistent anonymous `user_id`. Detailed touchpoint table in `BLACK-HAT.md` and `WHITE-HAT.md`.

## Red Hat — Intuition & Risk Signals

Gut-level signals logged without proof; several were later confirmed as concrete findings.

- **Marketing copy outran engineering.** "Your key/photo never leaves your device" appears repeatedly in UI and policy text and is contradicted by the network code. Privacy assertions appear unverified against implementation — treat every privacy claim as suspect until code-checked.
- **Two of everything.** Two auth stacks (`PyJWT` vs `flask_jwt_extended`), two quota systems (Redis daily vs DB monthly columns), two "am I in prod?" signals (`RAILWAY_ENVIRONMENT` vs `FLASK_ENV`), historically two `SubscriptionService` classes. Each pair is a "fixed it in one place, not the other" trap.
- **"Fail open" is the house style.** Quota checks, content moderation, and revocation all degrade *open* on infrastructure failure. The controls that protect cost and child safety switch themselves off exactly when things break.
- **Test scaffolding ships to production.** `/setup-test-account` and `generate-avatar-mock` sit on always-registered blueprints.
- **Interactive story mode was retrofitted.** It received keyword filtering but never the LLM classifier or the prompt sanitizer the main path has — uneven safety coverage between modes.
- **Allowlist-by-omission.** `sanitize_story_request` protects a named set of fields; any new free-text field is unprotected by default. Three fields already slipped through.
- **The highest-consequence surface is the least-guarded.** Custom-avatar pairs a real minor's photo with free text, yet `validate_prompt_safety` is wired only to the non-photo path.
- **Boot-time DDL.** Raw `ALTER TABLE` auto-migrations run at every worker boot, swallowing all errors as "non-fatal."
- Housekeeping smells: `saved_stories_screen.dart.temp` committed, `nixpacks.toml` + Dockerfile `CMD` + `railway.toml` all defining how the backend boots, a 277-line accreted `.gitignore`.

Full list in `RED-HAT.md`.

### COPPA §312 Sub-Section

- **Verifiable parental consent (§312.5(b)) — NOT MET.** Consent is a single checkbox after a 95% scroll; parent email is optional; the stored `consent_method` is hardcoded `email_verified` even when no email was entered and nothing was verified (H-8). No sliding-scale method (card transaction, signed form, KBA, ID) is implemented.
- **Notice accuracy (§312.4) — NOT MET.** The privacy notice states photos are never uploaded; they are (C-1). Consent built on inaccurate notice is invalid.
- **Collection before consent (§312.5(a)) — PARTIAL.** Child *name* is correctly deferred until after consent. Declared *age* is persisted before the consent gate (M-10); Firebase Analytics collects a persistent `user_id` and screen views before consent and regardless of age (M-9).
- **Data minimization / third-party disclosure (§312.8) — GAP.** Child first name and emotional-state data are sent to four third-party AI providers with no pseudonymization and incomplete disclosure (M-7); the Cloudflare image sub-processor is undisclosed (C-1 related).
- **Right to erasure / access (§312.6) — MET.** Backend erasure and access endpoints exist with rate limits and audit logging; client wires deletion to `DELETE /api/user/<id>/data`.

### PCI DSS SAQ-A Sub-Section

PCI scope is correctly minimal. Checkout and the billing portal are fully Stripe-hosted redirects; no PAN/CVV/expiry data touches the backend or client (`stripe_routes.py:95-120`). The webhook signature is verified (`construct_event`) and fails closed if `STRIPE_WEBHOOK_SECRET` is unset. SAQ-A eligibility is preserved. The payment *integrity* issues (H-2, M-3) are entitlement/authorization bugs, not cardholder-data exposure, and do not change PCI scope.

## Yellow Hat — Strong Controls Worth Preserving

These patterns are correct and should be protected against regression and replicated where gaps exist.

**Authentication & secrets**
- Fail-fast startup assertions reject a weak/dev JWT secret and missing prod Redis (`backend/app.py:139-176`).
- No hardcoded production secret fallbacks; `_get_required_secret` raises (`backend/config/__init__.py:30-49`).
- JWT decode pins `algorithms=['HS256']` — no `alg:none` / algorithm-confusion.
- BYOK keys encrypted AES-256-CBC at rest, never serialized (`encryption_utils.py`; `models/user.py:69`).
- Passwords via Werkzeug PBKDF2; refresh-token rotation with Redis JTI blocklist.

**API hardening**
- Explicit CORS allowlist with a documented rejection of `*.netlify.app` wildcards; never `"*"`.
- Strong security header set on API responses — HSTS, CSP, `X-Frame-Options: DENY`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy` (`app.py:307-366`).
- CSRF defense-in-depth: Origin/Referer enforcement on unsafe methods.
- No raw SQL string-formatting with user input — parameterized SQLAlchemy ORM throughout.
- Sentry `before_send` scrubs Authorization/Cookie/X-API-Key headers and bodies.
- COPPA erasure/access endpoints with strict rate limits and audit logging.

**Payments**
- Webhook signature verified (`construct_event`); refuses to run if `STRIPE_WEBHOOK_SECRET` unset.
- Checkout binds the authenticated user via `client_reference_id` + metadata; client-supplied `user_id` ignored. Amount/price never client-controlled. No card data on the server (SAQ-A preserved). (Note: the prior-audit "checkout omits user_id" finding is **resolved**.)

**AI / child safety**
- 14-pattern prompt-injection filter + delimiter stripping (`sanitizer.py`), `[USER_INPUT]` wrapping on the main story path.
- Server-side age clamp [2,120] and under-13 `minor_age_cap` enforcement.
- Two-layer output moderation (keyword + LLM classifier) with safe-fallback substitution on the main story path.
- Age-band-aware Gemini `SafetySetting` thresholds (`BLOCK_LOW_AND_ABOVE` for sexual/hate/harassment).
- IDOR ownership checks on characters, tasks, and interactive stories.
- Image ingestion hardened — 5 MB stream cap, dimension validation, thumbnail re-encode.

**Infrastructure & supply chain**
- Hash-pinned `pip-compile` lockfile (1300+ sha256 entries); `pip-audit` CVE scan in CI.
- Gitleaks `--staged --redact` pre-commit hook; `.gitleaksignore` suppresses only genuinely-public Firebase web keys.
- Multi-stage build for the frontend image; Celery hardened against pickle (`task_serializer='json'`).
- Dependabot configured; no `pull_request_target`; least-privilege `permissions` on the audit workflow; encrypted off-Railway Postgres backup.

**Client**
- Child name persistence correctly deferred until after consent.
- Analytics events transmit `character_name_length`, not the actual name.
- Cleartext HTTP restricted to `localhost`; re-consent enforced after privacy-policy updates.

## Green Hat — Alternatives & Novel Mitigations

- **Make the privacy claim true instead of correcting it.** On-device avatar generation (DiceBear-style deterministic rendering, already used for presets) would let "photos never leave the device" remain accurate and remove C-1, M-7's photo component, and the undisclosed sub-processor in one move. If server-side generation must stay, a client-side face-blur/abstraction step before upload reduces biometric exposure.
- **Pseudonymize at the prompt boundary.** Replace the child's real name with a per-request token (`HERO_1`) before any provider call and substitute it back locally. Cheap, removes the highest-value PII from all four third parties, and is a clean library-level fix for M-7.
- **One sanitization gateway, not an allowlist.** Replace `sanitize_story_request`'s named-field allowlist with a single recursive pass that sanitizes *every* string in the request and wraps it in `[USER_INPUT]`. This structurally eliminates the H-3/H-4/L-4 class — new fields are safe by default.
- **Fail-closed cost circuit breaker.** Split the quota system: keep the *availability* path fail-open, but back the *cost* breaker with a conservative DB counter so a Redis outage cannot uncap LLM spend (M-2). A global emergency rate cap on Redis-down is a one-flag mitigation.
- **Server-side entitlement as the only source of truth.** Treat all client premium flags as cosmetic; gate every paid capability on `User.subscription_tier` at the endpoint. This collapses M-8 and the H-2/M-17 confusion into a single trustworthy check.
- **Verifiable consent via the payment rail you already have.** Stripe is already integrated; a $0.50 authorize-and-void on a parent's card is a recognized COPPA sliding-scale method and reuses existing infrastructure for H-8 — stronger than an email round-trip, no new vendor.
- **Image-output classification.** Since Flux providers lack input moderation, run a lightweight vision-safety check on the *generated image* before it reaches a child (M-5). Moderating output is provider-agnostic and catches drift the input filter misses.
- **Per-user token version claim.** Add a `tv` claim; bump it on logout/data-deletion. Instant revocation without a per-request Redis lookup — fixes M-1 and the "deleted account keeps working" gap cheaply.
- **Unconventional vectors to keep in the threat model:** cross-field injection (a payload split across `worldBible` + `conflictHook` to evade per-field length caps); the `validate-api-key` endpoint as a distributed oracle to validate a corpus of leaked Gemini keys; voice-to-text as an injection channel that bypasses any client-side text validation.

### Chain-of-verification note
All three Critical findings were re-verified against source after the Black Hat pass:
- **C-2** — `git log --all -- backend/.env` confirms tracking until commit `f383b422`; `git show f383b422~1:backend/.env` confirms a `GEMINI_API_KEY=` entry (value not echoed). **Resolved during the audit:** the leaked key was tested against `generativelanguage.googleapis.com` on 2026-05-16 and returned `HTTP 400 / API_KEY_INVALID` ("API key expired") — Google no longer accepts it. The dead string remains in history but carries no risk; history-scrubbing is now optional/cosmetic. Severity effectively Informational.
- **C-1** — `custom_avatar_screen.dart:435` confirms `http.MultipartRequest` to `/avatar/generate-custom-avatar` from an `ImageSource.camera` selfie; `PRIVACY_POLICY.md:131` and `parental_consent_screen.dart:231,652` confirm the contradicting "never uploaded" claims.

Elevated from High to Critical per the audit's safety protocol (CSAM-adjacent risk involving a real minor's photo overrides CVSS).

High findings H-1, H-2, H-5 were re-verified by direct grep/read (test endpoint, webhook metadata flow, BYOK key transmission). No Critical/High finding was downgraded on re-verification; one (C-3) was upgraded.
